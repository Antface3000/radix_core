RADIX CORE - USER GUIDE
=======================

Radix Core is a local novelist studio. You can write, organize chapters, keep
a Story Bible and Lorebook, compile a manuscript, and spellcheck with no AI
at all. Optional Add Ons packs unlock local LLM writing, image generation, and
speech. Everything runs on your machine — no cloud APIs.

This guide explains the Qt interface. For installation see INSTALL.txt (also
under Help). Hover any control for a tooltip.


1. OVERVIEW
===========

- Studio first: manuscript, binder, Story Bible, lore, world state, compile,
  import, snapshots, and project search ship in the default install.
- Three packs (Add Ons, all off by default): Local LLM, Image, Audio.
  AI chrome (Team, Write/Chat dock, Image Gen, Voice, MOCK MODE) stays hidden
  until the matching pack is enabled. Download models/voices only after enable.
- Genre-agnostic: setting comes from each project's Story Bible, Lorebook, and
  World State, not from hardcoded world prompts.
- Single-slot models: one GGUF at a time so an ~8B model fits on 8GB VRAM.
- Tension Reader: chemistry/tension critique. Internal key horny_critic is
  legacy only; you will not see that word in the UI.


2. INTERFACE TOUR (PySide6)
===========================

The manuscript editor is always in the center. Feature panels open as floating
lightboxes from the left toolbar.

The left toolbar
----------------
Always: Story Bible, Projects, Focus, Add Ons, Help, Settings.
With packs: Team (LLM), Image Gen (Image), Voice (Audio).

Click a button to show that panel. Stay open pins a lightbox. Close or toggle
the button again to dismiss. Settings and Help stay as lightboxes.

The editor layout
-----------------
Binder (left) is the primary chapter list — drag to reorder. Metadata on the
current chapter: status (draft/revise/done), POV, location, story date.
Optional split view: Story Bible, lore list, or another chapter.
AI Assistant dock (right) appears only with the Local LLM pack.

The status bar
--------------
- Project name (click → Projects).
- Pack heartbeat dots (enabled packs only): LLM / Image / Audio.
- MOCK MODE (LLM pack on and no GGUF found). Click → Add Ons.
- Pending canon chip when agents staged lore for review.
- World State snippet (click → Story Bible → World State).
- Session and daily word counts, plus chapter word goal if set.

Typewriter scrolling and focus mode live in Settings → Editor, off by default.
They are not toolbar buttons.


3. THE EDITOR
=============

The center pane is a persistent, autosaving plain-text manuscript editor.

Binder and chapters
-------------------
The binder lists every chapter. The toolbar still has New / Rename / Delete
and a chapter dropdown. Each chapter stores status, POV, location, and story
date. Files live under data/projects/<id>/chapters/. Autosave after idle typing,
snapshots every few minutes, and a crash buffer for unsaved text.

Find and spellcheck
-------------------
Find in chapter (Aa / Word / .*). Spellcheck underlines misses; the replace bar
offers Replace, more suggestions, Ignore, and Add to dictionary. Optional
as-you-type autocorrect is in Settings → Editor (off by default). A grammar
checker can be dropped in later as radix_grammar.py on an extra plugin path
(Add Ons → extra directories) — it is not one of the three packs.

Export and import
-----------------
Export ▾ : current chapter, compile txt/md, standard manuscript layout, DOCX,
EPUB, and a production bible (tables of people/places/factions/creatures) for
collaborators who do not use Radix. Import Markdown or DOCX as a new chapter.
Project Search scans chapters, lore, and Story Bible (replace is chapters only).

Snapshots and notes
-------------------
Snapshots saves timed copies of the current chapter; restore from the dialog.
Notes (fix-later) sit beside the chapter in *.notes.json and are never sent to
Write/Chat unless you check Include notes in AI.

Gated actions (packs)
---------------------
- Brainstorm / Ask Agent — Local LLM pack.
- Visualize — Image pack (ComfyUI).
- Listen — Audio pack (speech).
- Summarize / Write / Chat / Query-blurb / continuity list — Local LLM pack.

Split view
----------
Use Split: Story Bible, Lore, or other chapter to keep research beside the
manuscript. Layout is local to the session.


4. EDITOR AI (Local LLM pack)
=============================

The AI Assistant dock appears only when the Local LLM pack is enabled.

Modes
-----
- Write — Prose Writer drafts the next passage; optional critics refine it.
  Voice lock (when you have accepted pages) matches your diction.
- Chat — project-aware conversation. Not inserted as manuscript.
- Query / blurb — named job for query letter, synopsis, or cover blurb. Never
  mixed into Write.

Retrieval over the full manuscript + lore supplements PREVIOUSLY for long books.
Continuity list (lore audit issues) appears under the editor; double-click to
jump to the lore entry.

Ghost text, draft bar, and shortcuts are unchanged: Ctrl+Enter run, Esc stop,
Ctrl+Shift+A accept, Ctrl+Shift+X reject, Ctrl+Shift+R retry.


5. STORY BIBLE
==============

Open from the left toolbar. Tabs:

- Bible: premise, genre, themes, rules, style, POV, tense, synopsis.
- Lorebook: typed canon entries — People, Creatures, Places, Things, Factions,
  Events, Concepts. Each type has its own context fields (e.g. creature type,
  habitat, powers for Creatures; territory, history for Places). Common fields:
  keywords, aliases, tags, portrait path, notes. Filter the list by type; use New to pick a type.
  Flags: Pinned and Always include in SETTING.
- World State: current date, location, scene notes, plus timeline, factions,
  ongoing events, and facts (one item per line).
- Outline: global and per-chapter summary and beats.

Save All writes all tabs. Export canon… saves a readable Markdown bundle.

Generate with AI (right-click)
------------------------------
Right-click any editable field → Generate with AI → pick T1/T2/T3 or
Orchestrated team. Enter a prompt; output streams into the field. Stop from
the same menu while generating. If the model emits [[REMEMBER]] or [[BIBLE:*]]
markers and auto-capture is on, canon is filed automatically.


Save your work: click Save Bible / Save World State / Save on lore entries.
Unsaved Story Bible edits are auto-saved when you run an agent (if the Story
Bible panel is open). The Team panel shows how many setting characters are
injected and has a Preview button for the full SETTING block.

Each text field on those tabs has a Generate button. Click it, enter a prompt,
pick T1 (Architect), T2 (Operator), T3 (Flavor), or Orchestrated, then Run.
Generated text streams into the field (appends if the field already has content).
Only one prompt row stays open at a time per tab.

Live lore auto-scan continuously matches your recent writing against the
Lorebook and surfaces relevant entries under the editor (and feeds them to the
AI). Configure it in Settings -> Editor.


6. TEAM AND ORCHESTRATION
=========================

The Team panel is the single place for multi-agent work. Three tabs:

- Specialist — message one enabled specialist with project setting context.
- Team run — one-shot job: the hidden system planner assigns specialists and
  runs them in order (no silent rewrite of their output unless you opt in).
- Project plan — generate a structured task list into plan.json, then run
  pending tasks one by one.

Controls (all tabs)
-------------------
- Persona menu (Specialist tab): pick a single specialist.
- Show <think>: reveal the model's hidden reasoning (debugging).
- Inject setting: include Story Bible + pinned lore + world state. The status
  line shows injected character count; Preview opens the full SETTING text.
- Insert into manuscript: append the latest output to the editor cursor.

How orchestration works
-----------------------
1. Plan: the system planner (architect model, not in the roster picker) emits
   a JSON task list with one specialist per task.
2. Execute: each specialist runs with only its scoped instruction (plus setting
   and explicit dependency outputs when a task depends on another).
3. Optional summary: enable "Team summary" in Settings → Orchestration if you
   want a labeled planner merge pass after the run (off by default).

Human-in-the-loop (HITL)
------------------------
Enable in Settings → Orchestration. The system liaison asks clarifying questions
before team runs and on ambiguity pre-flight checks.

NOTE: Cross-tier steps reload the model (single-slot), so a mixed pipeline
pauses between steps. This is expected.

The roster (specialists you can enable)
---------------------------------------
- Tier 1 - Architects: Canon Checker, Species Designer, Character Profiler,
  Setting Designer, Prose Writer, Line Editor, Dialogue Writer.
- Tier 2 - Operators: Session Summarizer, Plot Designer.
- Tier 3 - Flavor: Cliché Hunter, Spark Editor, Tension Reader, Dialect Writer.

Orchestration personas (system planner, system liaison) are hidden and use the
architect model only.


7. PROJECTS
===========

The Projects panel creates, switches, renames, and deletes isolated worlds. Each
project has its own chapters, lore, story bible, world state, outline, memory,
portraits, backgrounds, and (optionally) agent overrides. Switching projects
re-points the whole app.

Backup to folder… copies the project directory. Share lore/bible from another
project… links this book to a series parent so manuscripts stay per-book while
canon is shared.

On first launch (or when enabled in the startup dialog), a Projects launcher
opens before the main window so you can continue, open, or create a project.


8. FOCUS EXTRAS
===============

Open Focus from the left toolbar (opens as a movable lightbox; check Stay open
to keep it pinned). Tabs:

- Quick Add: bulk-add typed lore. One entry per line. Prefix with type:
  person: / character: / creature: / place: / world: / thing: / faction: /
  event: / concept: — then Name: notes. Pipe extra fields:
  creature: Smaug | type: dragon | notes: hoard guardian. Lines starting with #
  are ignored. Choose default type, Add vs Upsert, then Add to Lorebook.
- Research (not canon): parking lot scratchpad. Never auto-captured into lore.
- Canon Audit: rule-based lore report (duplicates, thin entries, keyword clashes,
  manuscript orphans). Double-click an issue to jump to the lore entry. Preview
  legacy upgrade runs the same migration as Story Bible → Upgrade legacy….
- Pre-Flight: readiness checklist (bible, lore, world state, chapters, setting
  depth, audit summary). Re-check re-runs it.


9. ADD ONS (PLUGIN PACKS)
=========================

Open Add Ons on the left. Each pack is a card: Enable, then Install.

Local LLM
  1. Install inference engine (prebuilt llama-cpp-python: NVIDIA GPU if
     nvidia-smi is present, otherwise CPU).
  2. Download writing models into models/. All three is about 15 GB; Architect
     only is enough for Write. Progress appears at the bottom of Add Ons.

Image
  ComfyUI is a separate app. Use “How to install ComfyUI”, then Browse to the
  folder that contains main.py (or Auto-detect), Launch, Sync assets.

Audio
  Install Piper for offline Listen. AllTalk is optional if you already have it.

Extra plugins: a folder that may contain radix_grammar.py. Not required.

Heartbeat dots on the status bar appear only for enabled packs. Comfy/AllTalk
are not started at launch unless that pack is on.


9b. SERVICE SYNC
================

Radix drives separately-running ComfyUI and AllTalk. Enable the Image or Audio
pack first, then use Add Ons to set folders, launch, and sync assets (copy-only).

Auto-launch: Start Radix Core.bat runs scripts/start_services.py. ComfyUI is
not auto-started. Piper is a per-call CLI. Heartbeat interval is in
Settings → Services (default 30 seconds).


10. SETTINGS CONTROL CENTER
===========================

Open Settings from the left toolbar (lightbox). Tabbed control center; changes
persist to data/global.json / data/agents.json and apply live.

- General: welcome/startup, update checks, lore audit-on-open, orphan scan.
- Generation: temperature, max tokens, streaming.
- Context: setting injection, capture mode, auto-capture, inject char cap,
  memory turns.
- Orchestration: max steps, HITL (liaison), optional team summary (off by
  default), ambiguity check, system planner/liaison keys.
- Editor: lore autoscan interval, match mode (substring / word boundary / regex
  keywords), find defaults (case, whole words, regex), Write/Chat pipeline,
  style guides, team defaults (default specialist, ideas persona).
- Agents: per-persona overrides (global vs project scope), reset project override.
- Services: ComfyUI / AllTalk URLs and folders, TTS, Piper, heartbeat interval.
- Image: workflow, dimensions, style prefix, seed behavior.
- Appearance: spellcheck, panel scroll/font, lightbox size and open mode (replace
  vs stack), editor font family, line height, word goal.

Panel lightboxes: toolbar buttons open floating panels; checked buttons show which
panels are open. Stay open keeps a panel pinned across switches. The editor uses
the full window width.


11. LORE CAPTURE MARKERS
========================

Agents persist canon by wrapping it in markers. With Auto-capture on (Settings ->
Context), tagged blocks update Lorebook, Story Bible, and World State.

Lorebook markers
----------------
- [[REMEMBER]] ... [[/REMEMBER]] - general fact (type depends on agent).
- [[CHARACTER:Name]] ... [[/CHARACTER]] - person (named preferred).
- [[NPC]] ... [[/NPC]] - person entry.
- [[CREATURE]] ... [[/CREATURE]] - creature (sets creature type fields).
- [[PLACE]] ... [[/PLACE]] - location.
- [[WORLD]] ... [[/WORLD]] - place (legacy alias for [[PLACE]]).
- [[THING]] / [[ITEM]] / [[OBJECT]] ... [[/THING]] - object or artifact.
- [[FACTION]] ... [[/FACTION]] - group or organization.
- [[EVENT]] / [[QUEST]] ... [[/EVENT]] - story event or quest beat.
- [[LORE]] ... [[/LORE]] - abstract concept or rule.

Story Bible markers
-------------------
- [[BIBLE:premise]] ... [[/BIBLE]] or [[PREMISE]] ... [[/PREMISE]]
- [[BIBLE:synopsis]] ... [[/BIBLE]], [[BIBLE:genreTone]] ... [[/BIBLE]], etc.
  (field name must match a Story Bible key: premise, logline, genreTone,
  worldRules, styleNotes, synopsis, themes, pointOfView, tense)

World State markers
-------------------
- [[WORLDSTATE:currentLocation]] ... [[/WORLDSTATE]]
- [[WORLDSTATE:currentDate]] ... [[/WORLDSTATE]]
- Shorthand: [[LOCATION]] ... [[/LOCATION]], [[DATE]] ... [[/DATE]], etc.

Use plain tags only (not **[[REMEMBER]]**). Unclosed [[REMEMBER]] lines are
still captured when possible.

Canon capture mode (Settings -> Orchestration)
----------------------------------------------
- Fill empty only - only blank fields and new lore entries are written.
- Append with note - adds captured text after a --- Added from agent --- line.
- Merge into one entry - combines into one lore entry or field, skipping
  duplicate paragraphs.

Orchestrated runs capture each agent step plus the Manager synthesis. Open
Story Bible tabs refresh automatically when capture succeeds.


12. TIPS AND TROUBLESHOOTING
===========================

- Everything says [MOCK ...]: no models are installed/loaded. That's normal on
  a fresh setup - see INSTALL.txt to add GGUF models.
- A pipeline pauses between agents: cross-tier steps reload the model
  (single-slot on 8GB). Expected.
- Out of VRAM: lower n_gpu_layers in Settings -> Models, reduce n_ctx, or drop
  the Flavor tier to a smaller 3-4B model.
- No images: confirm ComfyUI is running and the URL is set in Settings ->
  Services (health dot should be green), that the workflow file exists in
  workflows/, and that all five ComfyUI model files are installed (section 13).
- No voice: confirm the TTS engine in Settings -> Services (AllTalk URL
  reachable at http://127.0.0.1:7851, or run scripts/setup_piper.py / place
  piper.exe + voice in assets/piper/ - URLs in section 13).
- Buttons hard to see: the UI uses a lime-on-dark theme; secondary buttons are
  bordered surfaces. If colors look off, reset the theme in Settings ->
  Appearance.
- Reopen this guide: click ? in the top bar, or open Help from the top bar (or
  ... More drawer) and switch to User Guide.

14. UPDATES
===========

Current version is in the VERSION file and shown in the window title (v0.2.0+).

In-app: Help -> About & Updates -> Check for updates. If a newer release exists,
Update now runs update.bat and closes the app.

Manual: double-click update.bat in the radix_core folder.

  Git install: fetches and pulls origin/main, then reinstalls requirements.txt.
  Zip install: downloads the latest GitHub release zip (set RADIX_GITHUB_TOKEN
  for a private repo) and overlays files.

Always preserved: data/, models/, .venv/, assets/piper/

Maintainers: see RELEASE.txt and scripts/release.py.
